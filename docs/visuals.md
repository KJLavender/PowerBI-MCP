# 問畫面上的圖：「紅色是什麼意思？」

使用者看的是報表畫面，問的也是畫面：「紅色的字是什麼意思？」「北區那根長條為什麼是另一個顏色？」
「毛利率那條虛線是什麼？」「哪些門市是紅的？」。

用截圖回答這種問題一定會猜：圖片裡只有像素，看不出那根長條是哪個量值、在什麼篩選下算的、紅色是哪條規則；
互動式報表又截不完整。這裡不看畫面，而是**讀報表檔案**，報表是我們自己做的，`.pbix` / PBIP 在手上：

| 需要知道的 | 從哪裡來 |
|---|---|
| 每一頁有哪些圖、標題、類型、位置、用了哪些欄位與量值 | 報表版面（PBIR / `Report/Layout`） |
| 紅色、橘色代表什麼 | 作者的條件式格式規則、參考線、特別上色的成員（[catalog.md](catalog.md) 的作者意圖） |
| 量值怎麼算 | DAX，並展開成本報表其他量值或來源欄位的公式 |
| 畫面上的數字 | 分析引擎依**報表正在顯示的日期範圍**從快照計算 |
| 使用者現在選了什麼 | 報表旁的篩選列：它同時決定報表網址上的篩選與問答用的範圍，所以兩邊一定一致 |

## 工具：`explain_visual`

```
explain_visual(what="門市績效表上紅色的字", date="2026-10-17", window="day")
```

1. **指認**：從使用者的描述找出是哪張圖。線索都來自報表檔案：作者設定的顏色（「紅色」對到有紅色規則或紅色參考線的圖）、
   成員名稱（「北區」對到依區域分組的圖，北區被特別上色的再加分）、維度名稱（「門市」）、量值名稱、標題、圖表類型
   （「長條」「折線」「表格」；「報表」「圖表」這種泛稱不算）、「字」「底色」「線」、位置（「右上角」）。
   **只有一張明顯符合才往下解釋；有好幾張符合就列出候選，請使用者指定，不挑。**
2. **解釋**：顯示的欄位與角色（類別、圖例、數值）、每個量值的 DAX 與「用本報表的量值表示」的公式、
   這張圖的篩選、作者在這張圖的設定。
3. **數值與顏色**：依報表目前的日期範圍，算出這張圖每個成員的值，再依作者規則分組：哪些是紅、哪些是橘、哪些是綠。

問答 agent 呼叫這個工具時，會把使用者的原話一起帶進描述（模型常把「門市績效表上紅色的字」縮成「紅色的字」）；
上一題列出候選、這一題回「第一張」「後者」或說出圖名時，會自動對到那張圖。

## 畫面上的數字怎麼算

報表的日期範圍由篩選列決定：選了日期與時間窗，報表就套用 `[日期 − N 天, 日期]`（`analysis/visuals.py` 的
`REPORT_SPAN`，網頁也從伺服器讀同一組數字）；沒選日期就是全部期間。

量值先展開成「來源欄位上的彙總」（[catalog.md](catalog.md)），每個彙總對到快照裡的一個每日彙總，再在這段日期上加總、
套回公式。時間智慧照 DAX 的意思平移日期範圍：

| DAX | 計算方式 |
|---|---|
| `DATEADD(日期, -7, DAY)` | 同一段範圍往前 7 天 |
| `DATEADD(日期, -1, MONTH / YEAR)`、`SAMEPERIODLASTYEAR` | 往前一個月 / 一年（日期依月底調整） |
| `TOTALMTD` / `TOTALQTD` / `TOTALYTD` | 從範圍最後一天所在月 / 季 / 年的第一天開始 |

快照裡沒有的彙總（例如篩選了另一張表的 `CALCULATE`、跨多天的不重複計數）會寫明「無法從快照計算」，不估計。

**驗證**：2026-10-17、單日時間窗（報表範圍 2026-09-19 ～ 2026-10-17）時，門市績效表上 25 家門市的
銷售額、銷售額 週變動%、毛利率，和直接對 Oracle 下 SQL 算出的結果比對：**75 個值，0 個不一致**。

## 報表上的作者設定

為了讓問答有東西可以解釋，零售報表加上了報表作者常做的設定（`powerbi/build_pbip.py`，已存檔的 PBIR 只增加這些設定）：

| 圖 | 設定 |
|---|---|
| 區域與門市／門市績效 | 銷售額 週變動% 字色：< −10% 紅、−10% ～ 0 橘、≥ 0 綠；毛利率 < 45% 紅底 |
| 商品／各品類每月毛利率 | 「毛利率底線 45%」紅色虛線 |
| 總覽／各區域銷售額 | 只有北區改成橘色 |

Report Server 上的報表要重新發佈（`scripts/phase4-publish.ps1`）畫面上才看得到這些顏色。

## 問答評分

題庫（`agent/questions.yaml`）加了 5 題，答案都來自上面的設定與資料：

| 題目 | 期望 |
|---|---|
| 門市績效表上紅色的字是什麼意思？ | 週變動 < −10% |
| 報表上紅色的是什麼意思？ | 有兩張圖用了紅色（門市績效、毛利率底線），請使用者指定；不能說「沒有紅色」 |
| 2026-10-17 門市績效裡哪些門市的週變動是橘色的？ | 新北新莊店等 6 家（與 Oracle 驗證的值相同） |
| 各品類每月毛利率那張圖上的紅色虛線代表什麼？ | 45% 毛利率底線 |
| 總覽那張各區域銷售額，北區為什麼是不同顏色？ | 作者特別凸顯北區 |

開發時抓到的問題：

- 模型把描述縮短後找不到圖 → 由程式把原話帶進描述。
- 「報表上紅色的」的「表」被當成「表格」，只找到一張 → 比對圖表類型前先拿掉「報表」「圖表」。
- 使用者回「第一張」時，模型又用同樣的描述呼叫，只得到同一份候選 → 程式記住上一題的候選，把「第一張」換成圖名。
- `report_emphasis` 原本拿整體數字對照逐列套用的規則，模型據此說「整體毛利率 47.5%，所以報表上沒有紅色」，
  但規則是對每個門市套用，紅色虛線也一直都在 → 拿掉這個對照，改指向 `explain_visual`。

### 結果

完整題庫（2026-10-22，本機 `qwen3.5:4b`）：零售 20 題中模型回答通過 17 題、使用者拿到正確答案 18 題，**查核通過卻答錯 0**；
新增的 5 題與跨報表 4 題全數通過。沒過的 3 題是原有題目（模型把顯著性講錯或日期當成數字，被查核擋下），前幾輪也時有時無。
Excel 報表 15 題：使用者拿到正確答案 14 題（與改動前相同），查核通過卻答錯 0。

## 限制

- Report Server 沒有網頁上的 JavaScript API：使用者在報表**裡面**按的交叉分析篩選器、點的資料點，旁邊的面板讀不到；
  範圍以篩選列為準，回答會寫出用的期間。Power BI 服務 / Embedded 可以用官方 JavaScript SDK 讀到頁面、篩選與選取的資料點。
- 這張圖另有頁面 / 圖表層級篩選時，數值沒有套用那些篩選，回答會註明。
- 橫軸是日期的圖，數值是整段期間的合計，不是每一天。
- 只算目前這份報表的數字；其他報表（例如財務部報表）的圖可以指認與解釋，但沒有數值。
